## 0.8.0 — 2026-11-23 (package `com.nakamafarsi.unity` 3.23.0-nf.5)

Backup units from the server (Police Patrol server `nakama` @ d9c3469d1). Nothing in 0.7 changed.

- `BackupProvider.Use(key, attemptId, requestId, onComplete)` and `Use(key, attemptId, requestId, unitId, mission, onComplete)` (`pp_backup_use`, idempotent by `requestId`; an empty one gets `NewRequestId()`) answer the list with `Use` (`BackupUse`: `RequestId`, `Key`, `Kind`, `AttemptId`, `Mission`, `UnitId`, `Debited`, `Status`, `At`, `Replayed`, `Refunded`).
- `BackupProvider.Refund(requestId, onComplete)` (`pp_backup_refund`, only when the panel takes a unit at the call).
- Constants `BackupKinds` (`Ground`, `Air`), `BackupDebitModes` (`Arrival`, `Call`), `BackupErrorCodes` (`NotOwned`, `Limit`, `Cooldown`, `NotFound`, `UnitNotAllowed`, `StageNotRunning`, `RefundOff`, `RefundExpired`, `UseNotFound`, `RequestIdReused`). ## 0.6.1 — 2026-11-19 (package `com.nakamafarsi.unity` 3.23.0-nf.2, git `dev`)

- Samples: Police Patrol Quick Start logs `SDK_NOT_INITIALIZED` and stops when there is no SDK config, instead of a `NullReferenceException`.
- Poolakey installer (both layers): Unity 6 projects get the Unity 6 package, Unity 2020–2023 projects get the 2020_2023 package (`PoolakeyInstaller.PackageUrl`, `IsUnity6`).
- Ledger: item rows have `Unit` = the item key (Unity form) and `RefId` in Unity form; `LedgerProvider.List(..., refId)` sends `refId` to the server, so paging works with the filter (needs the server from this release: older servers refuse the field).
- Inventory: an owned item whose sale was stopped in the panel stays in `InventoryProvider.Get` with `PlayerItem.SaleStopped = true` (it cannot be bought). Unlocking it answers `InventoryErrorCodes.SaleStopped` (`INVENTORY_ITEM_SALE_STOPPED`, server `ITEM_SALE_STOPPED`); upgrading it is allowed unless the panel turned that off.
- Shop: `Product.PhoneRequiredFor` (payment methods that need a verified phone for this player, from `phoneRequiredFor`), `Product.PhoneVerified`, `Product.NeedsPhoneFor(method)`, `ShopItem.PhoneRequiredFor` and `ShopItem.NeedsPhone` (for the store of this build). `zarinpal` from the server is shown as `PaymentMethods.Zarrinpal`.
- Logging (Farsi layer): the base layer (socket, session, chat, analytics) writes to its logger only when `Logging` is on (`NakamaFarsiOptions.Logging`, set from the PP config). New: `SwitchedLogger`.
- Username errors: `UserErrorCodes.ReasonSeparatorEdge` (`separator_edge`, what the server sends) and `ReasonTaken` (`taken`); `ReasonDotEdge` is `[Obsolete]`. When the server sends a bare code (errors in code mode), the SDK fills `Meta.reason` from the server code (`ApiError.ServerCode`), so `reason` is always there.
- Error texts: a placeholder the server sent no value for is no longer shown raw. `{retryAfter}` becomes "a few" / «چند», any other one is dropped (`ErrorCatalog.Fill`). A top-level `retryAfterSeconds` fills `{retryAfter}`. `OTP_TOO_SOON` without a wait (errors in code mode) gets the wait from the last code sent to the same number (`ApiError.RetryAfterSeconds`, `Meta.retryAfter`, filled text). New: `ApiClient.VerificationResendAt`.
- Chat (Farsi layer): `ChatClient.Rejoined` is raised on the main thread (through the client dispatcher), like `MessageReceived`.
- Phone change: `AuthProvider.VerifyPhoneChangeStep` answers a `PhoneChangeStep`: when the panel asks for a code to the old number first, the first right code gives `Done = false`, `WaitingForNewPhoneCode` and `NextChallenge` (the code sent to the new number); the second code gives `Done = true` and `User`. `VerifyPhoneChange` is `[Obsolete]` and now fails with `PHONE_NEW_CODE_SENT` after the first step instead of answering the unchanged user. `OtpChallenge.Stage` (`old` / `new`) and `OtpChallenge.SentTo` (shown number).
- Free ride: the chapter the SDK builds from the server's free-ride rewards (`campaign_freeride`) now has the key `StageProvider.FreeRideRewardsChapterKey` (`freeride-rewards`), so it no longer clashes with a real server chapter keyed `freeride` (the Police Patrol seed has one; `FreeRideChapterKey` names that chapter). A free-ride reward is `Unlocked` only when the player level reaches its `minLevel` (new `PlayerStage.MinLevel`); the chapter is unlocked from the lowest `minLevel`. Their `Mode` is `StageProvider.FreeRideMode`.
- Stages: `StageResult.Prizes` (economy prizes paid by this result: `PrizeKey`, `For` = `tier` / `milestone` / `freeride`, `Items`; item keys in Unity form) and `StageResult.PendingPrizes` (prizes the server will pay later, with `PrizeKey` or `PrizeGroupKey`). New model `StagePrize`.
- Coin purchases: `PaymentProvider.Initiate(productId, PaymentMethods.InApp, ...)` answers `PAYMENT_REWARD_PENDING` (meta `paymentId`) when the server took the coins but the reward is still being granted; the server retries it. A coin purchase that failed without taking coins no longer holds a one-time product for 45 minutes.
- OTP: `RequestLoginOtp` (sign-in or sign-up by phone, always `publication_otp_request`) and `RequestRecoverOtp` (a signed-in guest moves into the phone's account, always `account_phone_recover_request`). `ResendOtp` reuses the purpose saved by the first request (login, recover or password reset), so the silent device sign-in no longer turns a login resend into a recovery (`PHONE_NOT_REGISTERED` for a new phone). `RequestPhoneOtp` is `[Obsolete]`: it still picks the route from `HasSession` on the first request only.
- Payments: a successful payment whose reward is not granted yet answers `PAYMENT_REWARD_PENDING` (server code in `ApiError.ServerCode`); the store purchase is consumed only after the server verified the receipt; `RecheckPending` follows payments whose reward is pending; `Payment.RewardGranted`, `PaymentPoller.WaitForReward`, `PaymentPoller.IsVerified`.
- Myket: subscription products are left out of `ProductIAP.Load`, and `Buy` answers `SUBSCRIPTION_NOT_SUPPORTED` before Myket opens (`ProductIAP.SupportsSubscriptions`).
- Inventory: `Buy`, `Unlock`, `Upgrade` take an optional `requestId`; without one the SDK keeps the same id for retries of the same action until it succeeds or fails with a final error (network, 429, 5xx and `INVENTORY_BUSY_TRY_AGAIN` keep it), so a retry never charges twice. `Service` does the same when `requestId` is null. `InventoryProvider.IsRetryable`.
- Currencies: `CurrencyProvider.List` / `GetByKey` always read `economy_balances.wallet`; the storage `items` list no longer replaces it (coins showed 0 after the first storage reward).
- Prices: `PlayerItem.FinalPrices` (from `economy_inventory` `finalPrice`, tag discount applied; falls back to `Prices`), `PlayerItem.DiscountPercent`, `PlayerItem.HasDiscount`. Show `FinalPrices` on buy buttons: it is what `Buy` charges. Shop products already had `Product.FinalPrice` / `ShopItem.FinalPrice` (`finalToman`).
- Security: `Http Key` is gone (`PolicePatrolSdkConfig.httpKey`, `SdkOptions.HttpKey`, `NakamaFarsiConfig.httpKey`, `NakamaFarsiOptions.HttpKey`). Phone + password login, forgot / reset password and the sign-up OTP (`publication_otp_*`) now sign in silently with the device first when there is no session (`SystemInfo.deviceUniqueIdentifier`, or a stored id), then call the RPC with that session; a password or OTP login replaces the device session as before. Old config assets keep loading (the old field is ignored). New: `SdkOptions.DeviceId`, `NakamaFarsiOptions.DeviceId`, `NakamaFarsiClient.DeviceId`, `NakamaFarsiClient.EnsureDeviceSessionAsync`. Rotate any runtime http_key that was ever put in a build.
- Errors: fields the server sends next to `code` (the suspension notice `kind`, `until`, `reason`) are copied into `ApiError.Meta` when `meta` does not have them; date strings in error JSON stay as sent.
- Chat (Farsi layer): `JoinRoomAsync` keeps history by default (`persistence = true`); joined channels are joined again after the socket reconnects (`ChatClient.Rejoined`, `JoinedChannelIds`, `RejoinAsync`, `ForgetChannels`; logout forgets them).
- Stages: `StageErrorCodes.ServerOwned` (`STAGE_SERVER_OWNED`, the server owns this stage's result, for example a cup match; do not retry and do not drop a saved result because of it).
- Free ride: `campaign_freeride_claim` answering `REWARD_LIMITED` comes back as a `StageResult` with `RewardLimited` = the reason (`cooldown` / `daily_limit`), `IsRewardLimited`, `NextRewardAt` and `RewardsLeftToday`, not as an error. Paid claims carry `XpGained`, `Xp`, `Level`, `NextRewardAt` and `RewardsLeftToday`. `StageProvider.Start` for a free-ride stage still makes a local id without a server call; the server limits rewards by the group cooldown and the daily limit, not by the attempt time.
- Ledger: `LedgerKinds` match the server kinds (`Purchase`, `Gift`, `Asset`, `Stage`, `Prize`, `Admin`, `Initial`, `Other`). `GiftCode` (now `gift`), `AdminAdd` and `AdminUse` (now `admin`) are `[Obsolete]` aliases; `CheatCode` is `[Obsolete]` because the server has no such kind.
- Content Publish: a "Make live after upload" toggle (on by default, as before). Off sends `activate: false`, so a key with only `content:write` uploads a ready pack without `PACK_ACTIVATE_DENIED`; `ContentApi.PublishAsync(..., activate)` already had the parameter.
- Error texts: the cached catalog is reloaded when it is older than its `cacheSeconds` or `NakamaFarsiClient.ErrorCatalogTtl` (30 min) on the next server error and when the app resumes (at most once a minute); `NakamaFarsiClient.RefreshErrorCatalogIfStaleAsync`, `IsErrorCatalogStale`, and `PolicePatrolSdk.RefreshErrorTexts` force a reload.
- OTP: the pending phone code (shown phone, purpose, expiry from `expiresIn`, 10 min if absent) is saved in the SDK store (PlayerPrefs in Unity) and restored on the next start, so `VerifyOtp` / `ResetPassword` / `ResendOtp` work after the game was closed while the player read the SMS. Cleared on success, on logout and when it expires. New: `ApiClient.VerificationExpiresAt`.
- Asset Sync: ids that differ only in case (`Tiggo8` / `tiggo8`) are reported as duplicates and block the sync (`AssetPaths.Duplicates`, `AssetPaths.IdKey`), because item keys are lower-cased for the server.
- Samples: `Samples~` is now in the package (it was left out by `.gitignore`), adapted to this API (reward pending, consume rule, `RewardPendingPaymentIds`). New sample Police Patrol Mission Runner: the saved result is sent before a new attempt starts (no race with `Start`), network / busy errors keep it and block the new attempt, `STAGE_SERVER_OWNED` keeps it aside instead of deleting it. UnityCheck and UnityCompileCheck compile every sample.

## 0.6.0 — 2026-11-15

- Runs on the nakama-farsi server through `com.nakamafarsi.sdk`; the 0.5.21 public API of guide sections 1–8 is unchanged.
- Item keys: the server keeps keys lower case (`tiggo8`) with the Unity id in `metadata.gameId`; the providers translate both ways, so game code keeps `Tiggo8`.
- Error codes the server renamed come back with their 0.5.x names (`ApiError.ServerCode` has the new one).
- Phone + password sign-in (`LoginWithPhone`), password reset by SMS (`ForgotPassword` / `ResetPassword`, `ResendOtp`), `SetPassword` and `UpdatePassword` work as in 0.5.x (account plugin RPCs); `Login` with a wrong username or password answers `AUTH_INVALID_CREDENTIALS`.
- Sign-ins that return a session token (phone code, recovery, password) switch to a refreshable session through the number's login key.
- Config: optional `Http Key` for these calls before any device login.
- `PolicePatrolStats.Add` reports design events (id = stat key); `PolicePatrolAnalytics` is new.
- Editor tools use the new editor endpoints (assets, shop cards, stat cards, content packs) with devkit API keys.
- Not in 0.6.0: providers outside the guide (news, FAQ, quizzes, social, support chat, tasks, chance games, leaderboards, gifts, avatars, catalog lists).
